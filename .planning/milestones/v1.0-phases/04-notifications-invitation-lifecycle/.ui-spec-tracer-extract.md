## Component Inventory

**Focal point:** On the dashboard, the invitation cards remain the focal point (Phase 2). The heart indicator is deliberately a *peripheral* attractor — small, in the top bar chrome, drawing the eye only when the red dot appears. When the panel is open, the panel's topmost notification row is the focal point.

### 1. `NotificationBell` — top bar heart + dot

Mounted in `DashboardPage.jsx` inside the existing right-hand cluster (`<div className="flex items-center gap-2">`, line 90), as the **first** child — before the avatar, name, and logout. It is only ever rendered on the dashboard, which satisfies D-14's "polling on the dashboard only" without a shared context.

**Wrapper:** `<div className="relative">` — the desktop panel anchors to this.

**Button:**
```
type="button"
className="relative inline-flex h-11 w-11 items-center justify-center rounded-full
           text-text-secondary transition-colors hover:bg-cream hover:text-text-primary
           focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-accent focus-visible:ring-offset-2"
```

| State | Heart icon | Dot | Button background |
|-------|-----------|-----|-------------------|
| Resting (0 unread, panel closed) | Lucide `Heart`, `size={20}`, `text-text-secondary`, outline | absent | transparent |
| Hover / focus (any unread state) | `text-text-primary` (or stays `text-accent` if unread) | unchanged | `bg-cream` |
| Unread (>=1 unread, panel closed) | Lucide `Heart`, `size={20}`, `text-accent`, outline (no fill) | present | transparent |
| Panel open | Lucide `Heart`, `size={20}`, `text-text-primary` | absent (cleared optimistically on open) | `bg-cream` |
| Disabled | **never** — D-04: the icon is always clickable, even with zero notifications |

**Red dot:**
```
className="absolute top-2 right-2 h-2 w-2 rounded-full bg-accent ring-2 ring-white"
aria-hidden="true"
```
8px diameter, inset 8px from the button's top-right — which lands its center exactly on the 20px heart glyph's top-right corner inside the 44px button. The 2px white ring separates it from the heart stroke against the white top bar.

### 2. `NotificationPanel` — dropdown container

**Positioning:**

| Viewport | Classes |
|----------|---------|
| < 640px (mobile) | `fixed left-4 right-4 top-[72px]` — full width minus the 16px gutters that match the top bar's `px-4`; 72px = 64px top bar + 8px gap |
| >= 640px (sm+) | `sm:absolute sm:left-auto sm:right-0 sm:top-full sm:mt-2 sm:w-[360px]` — anchored under the heart button, right-aligned, extending leftward |

Same component, two widths. **No bottom sheet, no full-screen overlay, no backdrop scrim** (D-05). The panel does not push the invitation cards down — it overlays them.

> ⚠ **Do not place the panel inside a transformed ancestor.** A CSS `transform` on any ancestor creates a containing block for `position: fixed` descendants, which would silently re-anchor the mobile panel to that ancestor instead of the viewport. The one-shot bounce is therefore specified on a `motion.span` wrapping the heart glyph — a *sibling* of the panel, never a parent. An element's own transform does not affect its own containing block, so the panel's entrance animation is safe; an ancestor's would not be.

**Container:**
```
className="z-40 overflow-hidden rounded-xl border border-border bg-white shadow-lg"
```
`shadow-lg` matches the elevation of the Phase 2 SuccessModal and Toast. `z-40` sits below Toast/Modal (`z-50`) and above page content.

**Panel header** (sticky, gives the scroll region an anchor):
```
className="sticky top-0 border-b border-border bg-white px-4 py-3
           text-sm font-semibold text-text-primary"
```
Text: `notifications.title`. No "mark all read" button — D-08 makes it redundant. No close button — Escape and outside-click handle dismissal, and mobile has generous surrounding tap area.

**Scroll region:**
```
tabIndex={0}
role="region"
aria-label={t('notifications.title')}
className="max-h-[70vh] overflow-y-auto overscroll-contain
           divide-y divide-border sm:max-h-[420px]"
```
`tabIndex={0}` makes the scrollable region keyboard-operable (WCAG 2.1.1) — required because notification rows contain no focusable children. `overscroll-contain` prevents scroll chaining to the page body on mobile.

**No loading state, ever.** D-15: the poll already holds the full list, so the panel always opens with data (or with the empty state). Do not render `LoadingSpinner` inside the panel.

### 3. `NotificationRow`

One row per notification, newest first (D-06). Non-interactive — no click target, no hover state, no per-item dismiss (deferred).

```
className={`border-l-2 px-4 py-3 ${
  isHighlighted ? 'border-l-accent bg-cream' : 'border-l-transparent bg-white'
}`}
```
The `border-l-2` is present in **both** states (transparent when read) so the 2px never causes a content shift between states.

**Content, top to bottom:**

1. **Sentence** — `text-sm text-text-primary` (line-height 1.5, wraps freely; no truncation, no `line-clamp`). Safe to leave unclamped **only because the inputs are now bounded at the source** — see "Cross-Phase Amendment" below. Do not remove that cap without revisiting this rule.
   - With a name: `notifications.saidYes` → `"{{name}} said yes to your “{{title}}”"`
   - Name null or empty string: `notifications.saidYesAnonymous` → `"Someone said yes to your “{{title}}”"`
   - `recipient_name` is nullable in `backend/app/models/notification.py` (the recipient can use "Skip message"), so the anonymous branch is required, not optional.
   - **No inline bold on the name.** Rendered as a single interpolated string, deliberately avoiding `<Trans>` markup — it keeps both zh-TW and en translations natural sentences and keeps Phase 5's i18n pass simple. Hierarchy in the row comes from the message quote and the secondary-colored timestamp.
   - Preceded by an `sr-only` "New" marker when highlighted: `<span className="sr-only">{t('notifications.newLabel')} </span>`.

2. **Message quote** — rendered **only** when `recipient_message` is a non-empty string:
   ```
   className="mt-2 border-l-2 border-border pl-3 text-sm text-text-secondary"
   ```
   Max 30 characters by DB constraint, so it never needs truncation. **No italics** — synthesized oblique renders poorly for zh-TW CJK glyphs. The left rule carries the quotation semantics; no quotation marks are added.

3. **Relative timestamp** — `mt-2 text-sm text-text-secondary`, wrapped in `<time dateTime={iso} title={absoluteLocalString}>`.

**Row height varies** (2 to ~4 content lines in the worst case, more for zh-TW). This is accepted — volume is low and dividers (`divide-y divide-border`) carry the rhythm. Height is bounded by the input caps in the Cross-Phase Amendment, not by any truncation in this component.

### 4. Empty state (inside the panel)

Shown when the list is empty. The panel still opens; the heart is never disabled or hidden (D-04).

```
<div className="px-4 py-6 text-center">
  <Heart size={32} className="mx-auto text-border" strokeWidth={1.5} />
  <p className="mt-3 text-base font-semibold text-text-primary">{t('notifications.emptyHeading')}</p>
  <p className="mt-2 text-sm text-text-secondary">{t('notifications.emptyBody')}</p>
</div>
```
`mt-3` = 12px, a multiple of 4. Tone matches the Phase 1 dashboard empty state ("No invitations yet" / "Create your first invitation and share it with someone special.").

### 5. Non-UI: Silent Expiry (INV-07 / D-23)

**There is no UI for invitation expiry.** Expired invitations simply stop appearing in `GET /api/invitations`, so their cards vanish on the next dashboard load. Explicitly do **not** build:
- an "expired" card variant, tombstone, or ghost row
- a toast, banner, or modal on expiry
- a removal animation (there is no client-side event to hook — the card is absent on first render of the next session)

The Phase 2 days-remaining countdown (`dashboard.daysRemaining`) is the creator's only and sufficient advance warning. It is unchanged.

Notification retention (30-day sweep, D-07) is likewise invisible: old rows are simply absent from the next poll response.

### Relative timestamp formatting

Native `Intl.RelativeTimeFormat(i18n.language, { numeric: 'auto' })` — zero dependencies, correct for both `zh-TW` and `en`.

| Age | Rendering |
|-----|-----------|
| < 60 s | `notifications.justNow` (a literal key, not `Intl`, to avoid the bare "now" string) |
| < 60 min | `rtf.format(-minutes, 'minute')` — "5 minutes ago" / "5 分鐘前" |
| < 24 h | `rtf.format(-hours, 'hour')` — "2 hours ago" / "2 小時前" |
| < 7 days | `rtf.format(-days, 'day')` — "3 days ago" / "3 天前" |
| >= 7 days | `Intl.DateTimeFormat(i18n.language, { month: 'short', day: 'numeric' })` — "Jul 30" / "7月30日" |

The 30-day retention window (D-07) bounds the maximum age, so no year is ever needed. `created_at` is timezone-aware from the backend; parse the ISO string directly.

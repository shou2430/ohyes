## Interaction Contracts

### Open the panel

1. User clicks/taps the heart button (or presses Enter/Space while it is focused).
2. Panel mounts and animates in (see Animation Specifications).
3. **Snapshot the highlight set before anything else:** `highlightedIds = notifications.filter(n => !n.is_read).map(n => n.id)`, stored in component state for this open only.
4. Optimistically clear the red dot: set every local notification's `is_read` to `true`.
5. Fire the mark-read request (D-08 — one call for everything, no per-item action).
6. Move focus to the panel scroll region.

No loading state at any point in this sequence.

### Unread highlight and its session decay (D-09)

- The highlight set is captured **once per open**, at step 3 above, from the state that existed before step 4's optimistic flip.
- While the panel stays open, the highlight does **not** change, fade, or animate away. A decaying highlight would read as a rendering bug.
- On the **next** open, step 3 runs against a list where `is_read` is already `true` for those items, so `highlightedIds` is empty and they render in the plain style.
- Read state is visual only: nothing is hidden, moved, reordered, or collapsed (D-09).
- If a *new* notification arrives via poll while the panel is open, it appears at the top of the list **without** highlight (it was not in the snapshot) and the dot does not reappear until the panel is closed and the next poll runs. Accepted: this edge is vanishingly rare at v1 volume and keeps the snapshot rule single-sourced.

### Mark-read failure (D-10)

Fails silently. No toast, no revert, no retry, no console-visible user feedback. The dot naturally reappears on the next 30-second poll because the server still has `is_read = false`. This is deliberately different from the delete/copy flows, which do toast on failure (Phase 2 D-18) — those are user-initiated, this is not.

### Dot appears (D-16)

**Dot visibility is exactly:**
```
showDot = unreadCount > 0 && !panelOpen
```
State this explicitly in the implementation. Without the `&& !panelOpen` term, the optimistic clear (open step 4) and the 30-second poll fight over the dot: a notification arriving after the mark-read call is genuinely unread server-side, so the next tick while the panel is still open would re-raise the dot underneath the open panel.

When the derived unread count transitions from `0` to `>0` (poll tick or first load), the heart plays a **one-shot** spring bounce and the dot scales in. Once per transition — never on every poll tick, never while the count merely grows from 1 to 2.

No toast, no sound, no `document.title` change (D-12 — the title stays "Dashboard - OhYes"), no browser Notification API.

### Close the panel

The panel closes, focus returns to the heart button, and the exit animation plays on any of:

| Trigger | Detail |
|---------|--------|
| Heart button click | Toggles closed |
| `Escape` keydown | Listener on `document` while open; `preventDefault` so it does not bubble into anything else |
| Pointer down outside | `pointerdown` listener on `document`; ignore events whose target is inside the wrapper (panel or button) |
| Focus leaves the wrapper | `focusout` on the wrapper where `relatedTarget` is outside it — covers Tab-away, since the panel is non-modal |
| Route change | Unmounting `DashboardPage` tears down the panel and stops the poll (D-14) |

**No focus trap.** The panel is a non-modal disclosure containing static content; trapping focus would strand keyboard users. Escape + focusout is the correct pattern.

### Polling (D-13, D-14, D-15, D-17)

- `setInterval` 30 000 ms, started on `NotificationBell` mount, cleared on unmount. Because the bell only mounts inside `DashboardPage`, this satisfies "dashboard only, not `/create`, not lifted into a shared context."
- Each tick fetches the **full** list (`GET /api/notifications`) with the `Authorization: Bearer` header from `localStorage.getItem("ohyes_token")`, matching the existing dashboard fetch pattern.
- Unread count is derived client-side: `notifications.filter(n => !n.is_read).length`. It is never rendered as a number — no badge (D-02) — only as the dot's presence and in the button's `aria-label`.
- **401:** clear `localStorage` and redirect to `/` (Phase 1 D-03).
- **Network error:** ignored silently, retried on the next tick. No toast, no backoff, no circuit breaker, no offline indicator.
- Timestamps re-derive on each render, so the 30-second tick refreshes them for free. Do not add a second timer for the clock.

### Relative timestamp formatting

Native `Intl.RelativeTimeFormat(i18n.language, { numeric: 'auto' })` — zero dependencies, correct for both `zh-TW` and `en`.

| Age | Rendering |
|-----|-----------|
| < 60 s | `notifications.justNow` (a literal key, not `Intl`, to avoid the bare "now" string) |
| < 60 min | `rtf.format(-minutes, 'minute')` — "5 minutes ago" / "5 分鐘前" |
| < 24 h | `rtf.format(-hours, 'hour')` — "2 hours ago" / "2 小時前" |
| < 7 days | `rtf.format(-days, 'day')` — "3 days ago" / "3 天前" |
| >= 7 days | `Intl.DateTimeFormat(i18n.language, { month: 'short', day: 'numeric' })` — "Jul 30" / "7月30日" |

The 30-day retention window (D-07) bounds the maximum age, so no year is ever needed. `created_at` is timezone-aware from the backend; parse the ISO string directly.

## Animation Specifications

All Motion (Framer Motion) 12.x. Every animation in this section is skipped when `prefers-reduced-motion: reduce` — the dot and panel then appear and disappear instantly.

### Heart one-shot bounce (on dot appearance)
```
animate: { scale: [1, 1.25, 0.92, 1.08, 1] }
transition: { duration: 0.6, ease: "easeOut", times: [0, 0.25, 0.5, 0.75, 1] }
```
Applied to a `motion.span` wrapping the `Heart` glyph, not to the button (the button's 44px hit area must not move). Keyed off a counter that increments only on the `0 -> >0` transition so the keyframe array replays exactly once.

### Red dot entrance
```
initial:    { scale: 0 }
animate:    { scale: 1 }
transition: { type: "spring", stiffness: 500, damping: 15 }
```
Matches the Phase 3 dodge-counter badge entrance family (spring, stiffness 400–500, damping 15).

### Red dot exit (on panel open)
```
exit:       { scale: 0, opacity: 0 }
transition: { duration: 0.15 }
```
Via `AnimatePresence`.

### Panel open / close
```
initial:    { opacity: 0, y: -8, scale: 0.98 }
animate:    { opacity: 1, y: 0,  scale: 1 }
exit:       { opacity: 0, y: -8, scale: 0.98 }
transition: { duration: 0.15, ease: "easeOut" }
style:      { transformOrigin: "top center" }        // mobile
style:      { transformOrigin: "top right" }         // sm+ — matches the anchor
```
Wrapped in `AnimatePresence` so the exit plays. Deliberately fast (150ms) — this is chrome, not a moment. Contrast with the Phase 3 screen transitions at 400ms.

### Row entrance
**None.** Rows render statically when the panel opens. A staggered list entrance would fight the 150ms panel transition and delay reading. New rows arriving via poll while the panel is open also appear without animation.

### Reduced motion
```
const reduce = useReducedMotion();   // from "motion/react"
```
- Bounce: skipped entirely (no scale keyframes).
- Dot entrance/exit: `transition: { duration: 0 }`.
- Panel: `transition: { duration: 0 }`, no `y` or `scale` offsets — opacity 1 immediately.

## Copywriting Contract

All strings are authored as i18n keys in **both** `frontend/src/i18n/en.json` and `frontend/src/i18n/zh-TW.json` under a new `notifications` namespace, matching the Phases 1–3 convention. zh-TW is the default language (`i18n/index.js` sets `lng: "zh-TW"`).

| Element | Copy (en) | Copy (zh-TW) | i18n Key |
|---------|-----------|--------------|----------|
| Primary interactive affordance (icon-only heart, `aria-label`, 0 unread) | Notifications | 通知 | `notifications.title` |
| Heart `aria-label` (with unread) | Notifications, {{count}} unread | 通知，{{count}} 則未讀 | `notifications.ariaUnread` |
| Panel header | Notifications | 通知 | `notifications.title` |
| Notification sentence (named) | {{name}} said yes to your “{{title}}” | {{name}} 對你的「{{title}}」說了 Yes | `notifications.saidYes` |
| Notification sentence (no name) | Someone said yes to your “{{title}}” | 有人對你的「{{title}}」說了 Yes | `notifications.saidYesAnonymous` |
| Unread screen-reader marker | New | 新 | `notifications.newLabel` |
| Timestamp, under 60s | Just now | 剛剛 | `notifications.justNow` |
| Empty state heading | No news yet | 還沒有新消息 | `notifications.emptyHeading` |
| Empty state body | When someone says yes, you'll see it here. | 當有人對你說 Yes，就會出現在這裡。 | `notifications.emptyBody` |
| Error state | **None — intentional.** | | |
| Destructive confirmation | **None — intentional.** | | |

**Error state, explicitly N/A.** This phase surfaces no error copy, by decision:
- Mark-read failure is silent (D-10) — no toast, no revert.
- Poll network failure is silent and retried (D-17).
- Poll 401 redirects to the landing page rather than showing a message (D-17, Phase 1 D-03).
- The existing `errors.network` key remains available for the rest of the dashboard and is deliberately **not** wired to any Phase 4 path.

**Destructive actions, explicitly N/A.** No user-facing destructive action exists in this phase's UI. Invitation and notification deletion are performed by the hourly backend sweep with no confirmation surface, no undo, and no notice (D-21, D-23). The existing Phase 2 delete-invitation confirmation is unchanged and out of scope here.

**Copy notes for the translator/executor:**
- `“ ”` in the en string are typographic curly quotes (U+201C / U+201D); zh-TW uses corner brackets `「 」` (U+300C / U+300D), which is the correct Traditional Chinese quotation convention. Do not substitute straight quotes.
- `{{count}}` in `notifications.ariaUnread` uses i18next interpolation, not pluralization — zh-TW has no plural forms and the en string reads correctly for 1 ("1 unread").
- Do not add a "Mark all as read" string. D-08 makes the action implicit.
- Do not add a "See all notifications" / "View all" link. There is no dedicated route (D-01).
- Both counters from the Cross-Phase Amendment need **no i18n key**. They render as `{title.length}/100` and `{name.length}/20` — digits and a slash, identical in both languages. This matches the shipped `MessageCard` counter, which also hardcodes `{message.length}/30`. Do not invent `create.titleCounter` or `recipient.nameCounter` keys.
- The backend `max_length` rejections need no new user-facing copy either: `maxLength` on each input makes the over-limit character unreachable in the UI, so the validators are defence-in-depth guards a normal user never triggers.
- **Do not change `recipient.namePlaceholder` or `recipient.nameLabel`** to advertise the 20-character limit. The counter carries that information; duplicating it in the label would crowd a field that is already tight at 375px.

## Responsive Behavior

Mobile-first. 375px is the minimum supported viewport.

| Breakpoint | Layout |
|------------|--------|
| 375–639px (mobile) | Heart button 44x44, first in the top bar right cluster. Panel is `fixed`, spanning `left-4 right-4` (343px wide at 375px) at `top-[72px]`. Max height `70vh` with internal scroll. Panel horizontally aligned to the page gutters, not to the button. Transform origin: top center. |
| >= 640px (sm) | Panel becomes `absolute`, `w-[360px]`, anchored `right-0 top-full mt-2` on the button wrapper, extending leftward. Max height `420px`. Transform origin: top right. Top bar gutter becomes `px-8` (existing). |
| >= 1024px (lg) | No further change. The panel is already at its terminal size. |

At 375px the notification sentence wraps to at most ~3 lines of Latin text (~6 lines of zh-TW) in the worst case, given the 100-character title cap and the 20-character name cap. Wrapping is expected and unstyled — no truncation, no `line-clamp`, no ellipsis. Recipient messages are DB-capped at 30 characters and never wrap past 2 lines.

The heart button and its 44px target are identical at every breakpoint — the panel is the only responsive element.

## Accessibility

**Disclosure pattern (not a menu).** The rows are static content, not actionable items, so `role="menu"` / `role="menuitem"` would be wrong (they promise arrow-key navigation and activation that do not exist).

| Concern | Contract |
|---------|----------|
| Trigger semantics | `<button type="button">` with `aria-expanded={open}` and `aria-controls="notification-panel"` |
| Trigger name | `aria-label` from `notifications.title` (0 unread) or `notifications.ariaUnread` with count (>=1 unread). The button is icon-only and has no visible text. |
| Panel semantics | `<div id="notification-panel">`; the scroll region carries `role="region"` and `aria-label={t('notifications.title')}` |
| Focus on open | Moves to the panel scroll region (`tabIndex={0}`), making Escape and focusout behave naturally |
| Focus on close | Returns to the heart button in every close path (Escape, outside click, toggle, focusout-to-outside) |
| Focus trap | **None.** Non-modal disclosure — trapping would strand keyboard users. |
| Escape | Closes the panel, returns focus to the button |
| Tab | Not intercepted. Tabbing out of the wrapper closes the panel via `focusout`. |
| Scrollable region keyboard access | `tabIndex={0}` on the overflow container (WCAG 2.1.1) — required because rows contain no focusable children |
| Focus visible | `focus-visible:ring-2 focus-visible:ring-accent focus-visible:ring-offset-2` on the heart button, matching the Phase 1 focus contract |
| Decorative elements | Red dot: `aria-hidden="true"`. Empty-state `Heart` icon: `aria-hidden="true"`. |
| Unread conveyed non-visually | `sr-only` "New" prefix inside each highlighted row's sentence, plus the count in the button's `aria-label` |
| Live regions | **Deliberately none.** A polling `aria-live` region would announce every 30 seconds and interrupt screen-reader users. New notifications are discovered when the user next focuses the heart button, whose `aria-label` carries the count. This is a considered restraint, not an omission. |
| Timestamps | `<time dateTime={isoString} title={absoluteLocalString}>` so assistive tech and hover both expose the exact time behind the relative phrasing |
| Touch targets | Heart button 44x44 on all viewports. Rows are non-interactive and therefore exempt. |
| Reduced motion | `prefers-reduced-motion: reduce` disables the bounce, the dot spring, and the panel transition (see Animation Specifications) |
| Contrast | All combinations meet WCAG AA — see the Color section |
| Language | Panel content inherits the document language from i18next; no `lang` attribute overrides needed |

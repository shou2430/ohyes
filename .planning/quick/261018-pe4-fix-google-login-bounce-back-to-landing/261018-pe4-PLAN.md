# Quick 261018-pe4: Fix Google login bouncing back to landing page

## Problem
OAuth flow completes (login → Google → /api/auth/callback → /auth/callback?token=...), but the
user lands back on `/`. `AuthProvider` mounts on `/auth/callback`, runs `checkAuth()` before
`AuthCallbackPage` stores the token, so it resolves `user=null, loading=false`. The callback page
then stores the token and navigates to `/dashboard`; `ProtectedRoute` sees `user=null` and
redirects to `/`. No `/api/auth/me` request is ever made (confirmed in prod Network tab).

## Tasks

### Task 1: Add `login(token)` to auth context + pure auth API helper
- files: frontend/src/context/auth-api.js (new), frontend/src/context/AuthContext.jsx
- action: Extract `TOKEN_KEY`, `authHeaders`, `fetchCurrentUser(token)` into `auth-api.js`.
  `AuthProvider` exposes `login(token)` which stores the token, fetches `/api/auth/me`, sets
  `user`. Stale-response guard: `checkAuth` / `fetchCurrentUser` only clear the token or set
  state if the stored token is still the one they used (an old expired token's 401 must not wipe
  a freshly stored token).
- verify: vitest unit tests for `fetchCurrentUser`
- done: tests pass

### Task 2: AuthCallbackPage awaits login before navigating
- files: frontend/src/pages/AuthCallbackPage.jsx
- action: `await login(token)` then navigate to `/dashboard`; on failure navigate to `/`.
  Ref guard so StrictMode's double effect doesn't call login twice.
- verify: `pnpm test`, `pnpm lint`, `pnpm build`; manual prod check after deploy
- done: login lands on /dashboard

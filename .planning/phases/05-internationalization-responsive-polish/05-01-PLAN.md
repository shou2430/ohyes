<objective>
Deliver UI-02: a bilingual (Traditional Chinese default + English) language toggle, proven
end-to-end on one page first (tracer), then rolled out to every creator page, with a
completeness/quality audit of the two translation files.

Purpose: The app must literally default to zh-TW and let the creator flip to English with no
page reload (ROADMAP Phase 5 success criteria 1 & 2). Persistence is client-only and
non-security by design (D-01).
Output: A `LanguageToggle` component; i18n init that resolves language from `localStorage`
(key `ohyes_lang`) else the zh-TW default and keeps `document.documentElement.lang` in sync;
`index.html` defaulting to `lang="zh-TW"`; and audited `en.json` / `zh-TW.json`.

Decisions implemented here: D-01 (localStorage persistence, no browser detection),
D-02 (top-right toggle on all creator pages), D-03 (`<html lang>` reflects active language,
default zh-TW), D-04 (recipient flow has no toggle; creator content never translated).
Sibling plans cover the rest of Phase 5: 05-02 → UI-01 (responsive), 05-03 → UI-03 (load perf).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser localStorage → app | The `ohyes_lang` preference is client-owned storage; the user can edit it via DevTools. |
| static translation JSON → rendered DOM | Developer-authored `en.json` / `zh-TW.json` values render as React children (auto-escaped). Not user input. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-01 | Tampering | `localStorage` key `ohyes_lang` | low | accept | Value is a UI-language preference with no security role (D-01). Tampering only changes which language renders. Defense-in-depth: init validates the stored value against the `{en, zh-TW}` allow-list and falls back to `zh-TW` on any unexpected value, so a tampered key cannot break rendering. |
| T-05-02 | Information Disclosure / Injection | translation strings rendered via `t()` | low | accept | Translation values are developer-authored static assets, not user input, and render as React children (React auto-escapes; no `dangerouslySetInnerHTML`) — no injection vector. |

No high-severity threats — no blocking security checkpoint required (ASVS L1, block-on-high).
No new package installs in this plan (all libraries already in `package.json`) → no supply-chain (T-05-SC) surface introduced here.
</threat_model>

Deliver UI-01: a 375px mobile responsive audit-and-fix pass across every OhYes page and
recipient component, using Tailwind utility-class edits only — no structural re-layout (D-05).

breakpoints (NoButton, PasswordGate, PostcardKeepsake, DodgeCounter, InvitationReveal), then
sweeping the creator pages (Landing, Dashboard, Create) and the recipient gate page

dodge behavior must not change.

with touch-friendly tap targets." The app is a pure SPA behind auth/password; the recipient
flow is the emotional peak and is most likely to be opened on a phone, so its zero-breakpoint
components are the highest-value fixes.
Output: Tailwind utility-class edits to nine existing files (no new files). This plan continues
the established `sm:/md:/lg:` breakpoint pattern already used in 34 places across 7 files — same
pattern, no new tooling, no new libraries (CLAUDE.md locks Tailwind CSS v4).

Decisions implemented here: D-05 (375px audit-and-fix, no structural re-layout, close the
zero-breakpoint recipient-component gap), D-06 (44×44px tap targets on Yes/general buttons and
links; No button exempt, dodge unchanged). Sibling plans: 05-01 -> UI-02 (bilingual toggle,
already placed on Landing/Dashboard/Create — this plan edits those SAME pages AFTER 05-01),
05-03 -> UI-03 (load perf).
</objective>

  behavior is a pure function of viewport width, evaluated independently per client.

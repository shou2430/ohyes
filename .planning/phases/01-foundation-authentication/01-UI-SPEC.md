# Phase 1 — UI Design Contract

> Visual and interaction contract for Foundation & Authentication.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none (utility-first Tailwind CSS v4) |
| Icon library | Lucide React (tree-shakeable, MIT, pairs with Tailwind) |
| Font | Inter (variable, loaded via Google Fonts CDN) |

**Rationale:** CLAUDE.md explicitly rejects component libraries (Chakra UI, Material UI) in favor of Tailwind utilities. Lucide provides clean, consistent icons at minimal bundle cost. Inter is a highly legible variable font that supports the playful-yet-clean tone.

---

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps, inline padding |
| sm | 8px | Compact element spacing, button internal padding |
| md | 16px | Default element spacing, card padding |
| lg | 24px | Section padding, form group gaps |
| xl | 32px | Layout gaps between major sections |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level vertical padding |

Exceptions: Google sign-in button touch target minimum 44px height (accessibility).

## Typography

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 16px | 400 (regular) | 1.5 | Descriptions, empty state text |
| Label | 14px | 500 (medium) | 1.4 | Navigation items, button text, metadata |
| Heading | 24px | 600 (semibold) | 1.2 | Page headings, dashboard title |
| Display | 36px | 700 (bold) | 1.1 | Landing page app name |

**Note:** Only 2 primary weights used (400, 600). Display at 700 is reserved exclusively for the app name on the landing page. Label at 500 is the medium fallback within Inter variable.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFF7F0` (warm cream) | Page backgrounds, main surfaces |
| Secondary (30%) | `#FFFFFF` (white) | Cards, top bar, input fields |
| Accent (10%) | `#E11D48` (rose-600) | See reserved list below |
| Destructive | `#DC2626` (red-600) | Logout confirmation, future delete actions |
| Text primary | `#1C1917` (stone-900) | Headings, body text |
| Text secondary | `#78716C` (stone-500) | Placeholder text, metadata, empty state body |
| Border | `#E7E5E4` (stone-200) | Card borders, input borders, dividers |

**Accent reserved for:**
- "Sign in with Google" button background
- Primary CTA buttons (future phases)
- Active navigation indicator
- Focus ring on interactive elements

**NOT for:** body text, borders, backgrounds, decorative elements.

**Visual tone (D-09):** Warm, inviting, playful. The warm cream background (`#FFF7F0`) avoids the clinical feel of pure white. Rose accent adds romantic energy without being aggressive. The palette says "personal gesture" not "enterprise tool."

## Interaction Contracts

### Google Sign-In Flow

1. User clicks GoogleSignInButton
2. Button enters loading state (spinner, text changes to "Signing in...")
3. Browser redirects to Google OAuth consent screen
4. Google redirects back to app
5. If success: redirect to `/dashboard`
6. If failure: return to landing page with toast "Sign-in failed. Please try again."

### Logout Flow

1. User clicks LogoutButton
2. No confirmation dialog (low-stakes action, easy to re-login)
3. Backend clears httpOnly cookie
4. Frontend redirects to `/` (landing page)

### Route Protection (D-08)

1. Unauthenticated user navigates to `/dashboard`
2. ProtectedRoute checks auth state
3. If no valid session: redirect to `/` immediately
4. No flash of dashboard content before redirect

## Responsive Breakpoints

| Breakpoint | Width | Adjustments |
|------------|-------|-------------|
| Mobile | < 640px | Full-width buttons, `md` (16px) page padding, stacked layout |
| Tablet+ | >= 640px | Auto-width buttons (min 200px), `xl` (32px) page padding |
| Desktop | >= 1024px | Max content width 1200px centered, TopBar max-width matches |

**Mobile-first:** All styles default to mobile. Breakpoints add desktop overrides.

## Animation (Phase 1 scope)

| Element | Animation | Library | Spec |
|---------|-----------|---------|------|
| GoogleSignInButton hover | Scale up | CSS (Tailwind `hover:scale-[1.02]`) | 150ms ease-out |
| Page transitions | Fade in | Motion (Framer Motion) | opacity 0 to 1, 200ms ease-out |
| Loading spinner | Rotate | CSS (`animate-spin`) | continuous 360deg, 1s linear |
| Toast notification | Slide in from top | Motion | y: -20 to 0, opacity 0 to 1, 300ms spring |

**Note:** Motion (Framer Motion) is in the tech stack per CLAUDE.md. Phase 1 uses it minimally for page transitions and toasts. Heavy animation usage begins in Phase 3 (No button escape behavior).

## Accessibility

| Requirement | Implementation |
|-------------|---------------|
| Focus visible | 2px accent ring with 2px offset on all interactive elements |
| Color contrast | Text primary on warm cream: 14.2:1 (AAA). Text secondary on warm cream: 5.1:1 (AA). |
| Button min size | 44px touch target height on mobile |
| Alt text | Google avatar: "{name}'s profile photo". Fallback initials: aria-label "{name}" |
| Skip nav | Not needed in Phase 1 (simple layouts with few elements) |
| Reduced motion | Respect `prefers-reduced-motion`: disable page transitions, keep spinner |

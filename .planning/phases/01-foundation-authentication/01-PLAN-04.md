# Plan 1-04: Deployment Config — Dockerfiles, Railway Static Site Setup

<objective>

The frontend is deployed as a Railway static site (no Dockerfile needed — Railway builds Vite output directly). The backend runs FastAPI with uvicorn in a Docker container. ```

Create `backend/Dockerfile`:
```dockerfile
FROM python:3.12-slim

# Install uv
COPY --from=ghcr.io/astral-sh/uv:latest /uv /uvx /bin/

WORKDIR /app

# Install dependencies first (cache layer)
COPY pyproject.toml uv.lock ./
RUN uv sync --frozen --no-dev

# Copy application code
COPY . .

# Create photo storage directory (Railway volume will mount over this)
RUN mkdir -p /data/photos

# Run with shell form to expand $PORT
CMD uv run uvicorn app.main:app --host 0.0.0.0 --port ${PORT:-8000}
```

This Dockerfile:
- Uses Python 3.12 slim base
- Installs uv from official image
- Caches dependency install separately from source copy
- Uses --no-dev to exclude test dependencies
- Creates /data/photos for Railway volume mount
- Uses shell form CMD to expand $PORT (Railway sets this dynamically)
- Falls back to port 8000 for local development
</action>

<action>
Update `backend/.env.example` to document all required environment variables and Railway setup:
```
# OhYes Backend Environment Variables
# ====================================
# Railway auto-injects: DATABASE_URL, PORT
# You must manually set: GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET, JWT_SECRET, SESSION_SECRET, FRONTEND_URL, API_URL
#
# Railway setup:
# 1. Create project with 2 services: backend (Docker), database (PostgreSQL plugin)
# 2. Add a static site service for frontend (set root directory to /frontend, build command: pnpm build, output directory: dist)
# 3. Set root directory for backend service to /backend
# 4. Attach persistent volume to backend at mount path /data/photos
# 5. Set FRONTEND_URL on backend to the frontend static site's Railway URL (e.g., https://ohyes-frontend.up.railway.app)
# 6. Set API_URL on backend to the backend service's Railway URL (e.g., https://ohyes-backend.up.railway.app)
# 7. Register OAuth redirect URI in Google Cloud Console: <API_URL>/api/auth/callback
# 8. Set VITE_API_URL on frontend static site service to the backend Railway URL

DATABASE_URL=postgresql://localhost:5432/ohyes
GOOGLE_CLIENT_ID=your-google-client-id
GOOGLE_CLIENT_SECRET=your-google-client-secret
JWT_SECRET=generate-a-random-secret-min-32-chars
SESSION_SECRET=generate-a-different-random-secret-min-32-chars
FRONTEND_URL=http://localhost:5173
API_URL=http://localhost:8000
PHOTO_STORAGE_PATH=./data/photos
```

Key difference from previous Caddy approach:
- No BACKEND_URL env var needed (no reverse proxy)
- OAuth redirect URI points directly to API_URL (not through frontend proxy)
- Frontend needs VITE_API_URL build-time env var to know where the backend is
- CORS on backend handles cross-origin requests
</action>

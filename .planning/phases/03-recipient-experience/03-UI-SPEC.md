# Phase 3 — UI Design Contract

> Visual, interaction, and animation contract for the Recipient Experience phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

| Property | Value |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, sparkle offsets |
| sm | 8px | Compact element spacing, input padding |
| md | 16px | Default element spacing, card padding |
| lg | 24px | Section padding, form field gaps |
| xl | 32px | Layout gaps between major sections |
| 2xl | 48px | Page top/bottom padding |
| 3xl | 64px | Vertical centering breathing room |

Exceptions: Touch targets on mobile must be minimum 44px height (h-11). The No button uses 48px height (h-12) to provide a larger tap target for the dodge mechanic.

## Interaction Contracts

### Password Gate — Submit

1. User types password into input field.
2. Submit button enables when input is non-empty.
3. User clicks "Unlock" or presses Enter.
4. POST to backend password verification endpoint.
5. **Correct password:** Transition to Screen 2 (Invitation Reveal). Slide transition: password gate slides out right, reveal page slides in from left. Duration 400ms, ease `[0.32, 0.72, 0, 1]`.
6. **Wrong password:** Input field shakes via Motion spring animation (see Animation Specs). Border turns `border-destructive`. Error text appears below: "Incorrect password". Error clears on next keystroke.
7. No attempt limit. Unlimited retries.

### No Button — Escalating Dodge Behavior

The No button dodge behavior uses 5 escalation stages based on a dodge counter. The counter increments each time the user's pointer enters the button's hit area (desktop: `onHoverStart`, mobile: `onTouchStart`).

#### Stage Definitions

| Stage | Dodges | Spring Stiffness | Spring Damping | Behavior |
|-------|--------|-------------------|----------------|----------|
| 1 — Shy | 0-2 | 200 | 20 | Gentle drift away from cursor. Moves 60-80px in the opposite direction of approach. Stays near original position. |
| 2 — Nervous | 3-5 | 350 | 15 | Quicker dodge. Moves 100-140px. Starts leaving sparkle trails (see Trail Effects). |
| 3 — Frantic | 6-9 | 500 | 12 | Fast dodge. Moves 160-200px. Trail density increases. Button slightly shrinks on each dodge (`scale: 0.95`). |
| 4 — Panicked | 10-14 | 700 | 10 | Very fast dodge. Moves 200-260px. Button wobbles after landing (`rotate` oscillation +/-3 degrees). Trail is dense. |
| 5 — Desperate | 15+ | 900 | 8 | Teleport-like speed. Moves to random position within viewport bounds. Button text cycles through desperate messages (see Copywriting). Maximum wobble after landing (+/-5 degrees). Trail is at maximum density. |

#### Dodge Vector Calculation
1. Compute vector from pointer position to button center.
2. Normalize the vector.
3. Multiply by the stage-appropriate distance (randomized within range).
4. Add random angular offset (+/-30 degrees) to prevent predictable paths.
5. Clamp final position to keep button within viewport bounds (16px padding from edges).
6. Animate to new position using Motion's `animate` with spring physics (`type: "spring"`, `stiffness`, `damping` from stage table).

#### Mobile Touch Handling
- On mobile, the dodge triggers on `onTouchStart` (finger touches the button).
- The button teleports to a new position immediately (no spring animation on mobile — spring feels sluggish on touch).
- Use `type: "tween"` with `duration: 0.15` on mobile instead of spring.
- Detection: Check `window.matchMedia('(pointer: coarse)')` or `'ontouchstart' in window`.

### No Button — Sparkle/Star Trail Effects

Sparkle particles spawn along the No button's movement path during and after each dodge (stages 2+).

#### Particle Specification
- Shape: 4-pointed star (CSS clip-path or SVG). Simple diamond/star shape.
- Size: Randomized between 6px and 14px.
- Color: 60% `#FBBF24` (amber-400 gold), 40% `#FFFFFF` (white).
- Spawn count per dodge: Stage 2: 3-5 particles. Stage 3: 5-8. Stage 4: 8-12. Stage 5: 12-16.
- Spawn position: Along the line between the button's start and end positions, with random offset of +/-20px perpendicular to the path.
- Animation: Each particle fades in (`opacity: 0 -> 1` over 100ms), holds for 200ms, then fades out and drifts downward (`opacity: 1 -> 0`, `y: +20px`, `scale: 0.5 -> 0`) over 600ms.
- Total particle lifetime: 900ms. Remove from DOM after animation completes.
- Use Motion's `AnimatePresence` + `motion.div` for each particle. Key each particle uniquely.
- Maximum particles on screen at any time: 40 (prevent performance issues).

### Yes Button — Click Flow

1. User clicks Yes button.
2. Button scales down briefly (`scale: 0.9`, duration 100ms) then back to 1.0.
3. Slide transition begins: entire invitation reveal screen slides out to the right (`x: 100%`, duration 400ms, ease `[0.32, 0.72, 0, 1]`). Message card (Screen 3) slides in from the left (`x: -100% -> 0`, same duration and ease).
4. No confetti. No hearts. Clean slide only (per D-04).

### Message Card — Submit

1. User fills in name (optional) and message (optional, max 30 chars).
2. User clicks "Send" or "Skip message".
3. POST to backend respond endpoint. Button shows "Sending..." loading state.
4. On success: Postcard animation transition.
   - **Primary (if feasible):** Message card folds inward (scale Y from 1 to 0, with perspective transform to simulate folding into an envelope). Duration 600ms. Then postcard (Screen 4) rises up from below (`y: 100% -> 0`, duration 500ms, spring physics).
   - **Fallback:** Simple slide transition — message card slides out right, postcard slides in from left. Same 400ms timing as other transitions.
5. On failure: Toast error notification. Re-enable send button.

### Dodge Counter — Display

1. Counter badge is hidden initially (before any dodge attempts).
2. On first dodge: Badge enters with `scale` animation (0 -> 1, spring, stiffness 400, damping 15).
3. On each subsequent dodge: Counter number updates. Badge does a brief `scale` pulse (1 -> 1.2 -> 1, duration 200ms).
4. Counter label text updates at stage boundaries (see Copywriting).

## Animation Specifications

### Password Shake (wrong password)
```
type: "spring"
stiffness: 600
damping: 15
mass: 0.5
animate: { x: [0, -8, 8, -6, 6, -3, 3, 0] }
duration: 0.4s total
```
Apply to the password input container (not just the input, so the border shakes too).

### Slide Transition (shared pattern for all screen transitions)
```
exit:  { x: "100%", opacity: 0 }
enter: { x: "-100%", opacity: 1 } -> { x: 0, opacity: 1 }
transition: { duration: 0.4, ease: [0.32, 0.72, 0, 1] }
```
Use Motion's `AnimatePresence` with `mode="wait"` to sequence exit then enter.

### No Button Spring (per stage)
```
type: "spring"
stiffness: {from stage table}
damping: {from stage table}
mass: 1
```

### No Button Wobble (stages 4-5, after landing)
```
animate: { rotate: [0, degrees, -degrees, degrees/2, -degrees/2, 0] }
transition: { duration: 0.5, ease: "easeOut" }
```
Stage 4: degrees = 3. Stage 5: degrees = 5.

### Sparkle Particle Lifecycle
```
initial: { opacity: 0, scale: 0.8 }
animate: { opacity: 1, scale: 1 }
exit:    { opacity: 0, scale: 0, y: 20 }
transition: {
  opacity: { duration: 0.1 },        // fade in
  exit:    { duration: 0.6, delay: 0.3 }  // hold 200ms then fade out
}
```

### Dodge Counter Badge Entrance
```
initial: { scale: 0 }
animate: { scale: 1 }
transition: { type: "spring", stiffness: 400, damping: 15 }
```

### Dodge Counter Pulse (on increment)
```
animate: { scale: [1, 1.2, 1] }
transition: { duration: 0.2 }
```

### Postcard Fold (primary, if feasible)
```
// Message card fold
animate: { scaleY: 0, opacity: 0 }
transition: { duration: 0.6, ease: [0.32, 0.72, 0, 1] }
style: { transformOrigin: "bottom center", perspective: "800px" }

// Postcard rise
initial: { y: "100%", opacity: 0 }
animate: { y: 0, opacity: 1 }
transition: { type: "spring", stiffness: 200, damping: 20, delay: 0.3 }
```

### Yes Button Click Feedback
```
whileTap: { scale: 0.9 }
transition: { duration: 0.1 }
```

## Accessibility

- Password input has associated `<label>` element (visually hidden if design requires, but present for screen readers).
- Password submit button has `aria-label="Unlock invitation"`.
- Password error announced via `aria-live="assertive"` region.
- Yes and No buttons have `role="button"` (implicit from `<button>` element).
- No button dodge: `aria-hidden="true"` on sparkle trail particles (decorative only).
- Dodge counter has `aria-live="polite"` to announce count changes to screen readers.
- Message form inputs have associated `<label>` elements.
- Character counter has `aria-live="polite"` to announce remaining characters.
- Slide transitions use `prefers-reduced-motion` media query: if user prefers reduced motion, replace all spring/slide animations with instant transitions (`duration: 0`). No button still dodges but without spring physics (instant position change).
- Color contrast: All text/background combinations meet WCAG AA. White on accent (rose-600) = 4.6:1 (passes AA for large text/buttons). Text-primary on cream = 14.5:1. Text-secondary on cream = 5.2:1.
- Postcard download button (if present) has `aria-label="Save postcard as image"`.

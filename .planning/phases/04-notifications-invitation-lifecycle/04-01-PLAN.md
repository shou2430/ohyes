Extend `backend/tests/conftest.py` with five fixtures. Import `AsyncSession` from
`sqlalchemy.ext.asyncio`, `engine` and `get_db` from `app.core.database`,
`create_access_token` from `app.core.security`, and `User` from `app.models.user`.

`db_session` — follow the RESEARCH Code Examples shape: `async with engine.connect() as conn`,
`await conn.begin()`, construct an `AsyncSession` bound to that connection, register an
`override_get_db` generator that yields it into `app.dependency_overrides[get_db]`, yield the
session, then `await session.close()`, `await conn.rollback()`, and pop the override.

Two concrete divergences from the RESEARCH snippet are required and must be applied:

1. Construct the session with `expire_on_commit=False` **and**
   `join_transaction_mode="create_savepoint"`. This is load-bearing, not cosmetic:
   `respond_to_invitation` (`backend/app/routers/invitations.py`) and the future
   `mark_all_read` both call `await db.commit()`. Without the savepoint mode that commit ends
   the outer connection transaction and the teardown rollback undoes nothing, leaking seeded
   rows into the next test — the exact WR-007 failure mode.
2. Pop the dependency override inside a `finally` so a failing test cannot leave
   `app.dependency_overrides` mutated for the rest of the session.

`client` — keep the existing `AsyncClient` + `ASGITransport(app=app)` + `base_url="http://test"`
body unchanged, but add `db_session` as a fixture parameter so every request issued in a test
resolves `get_db` to the rolled-back session.

`seeded_user` — depends on `db_session`. Builds a `User` with collision-free values
(`google_id` and `email` derived from `uuid4().hex`) and `display_name="Test Creator"`,
`db_session.add(...)`, then `await db_session.flush()` so `user.id` is populated. Use `flush`,
never `commit`. Returns the `User`.

`second_user` — identical shape, a second independent creator. This exists so the ownership
tests in Task 3 have a real second principal rather than a fabricated `user_id`.

`auth_headers` — depends on `seeded_user`, returns
`{"Authorization": "Bearer " + create_access_token(seeded_user.id)}`. Add a matching
`second_auth_headers` for `second_user`. Mint tokens through the production
`create_access_token`; do not hand-assemble a JWT and do not add a test-only auth bypass.

This plan adds **no product code**: no endpoint, no request handler, no component, no scheduler
wiring, no migration. It therefore introduces **no new runtime attack surface**. The register
below is deliberately short and states honestly which Phase 4 threats belong to other plans

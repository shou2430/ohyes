## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Empty-return-as-failure | Treating an empty `Agent()` return as a failed run. Cost a duplicated planner spawn before it was recognised. | blocking | Check the filesystem before retrying. Never re-spawn on an empty return alone. |
| Full-file planner inputs on a slow gateway | Letting each chunked planner run read the full 48KB `04-UI-SPEC.md` + 46KB `04-RESEARCH.md`. Caused one hard timeout on 04-02 and two on 04-03. | blocking | Pre-extract only the relevant slices into a small scratch file and point the agent at that. Put the FULL spec in the task's `<read_first>` so the executor still gets it. The `.ui-spec-*-extract.md` / `.research-*-extract.md` files in this directory are working examples — 04-02 succeeded on retry with the *same model*, only smaller inputs. |
| Proposing a config fix without verifying it resolves | `model_overrides.gsd-planner = "claude-opus-4-8"` was recommended, then found to be a verified no-op — GSD maps Claude full IDs back to bare aliases. | advisory | Run `resolveModelInternal(cwd, agent)` from `bin/lib/model-resolver.cjs` against a temp config copy before recommending any model setting. |
| Over-trusting a leaner plan | `04-03-PLAN.md` is 23KB vs 41-60KB for its siblings, because it fell back to sonnet after two opus timeouts. | advisory | It was handed to the checker with an explicit instruction to scrutinize it harder, and it passed with no blocker. If execution surfaces gaps, 04-03 is the first place to look. |
| Re-litigating the scheduler choice | APScheduler vs Celery/Redis was compared twice and settled both times. The deciding factor is the volume constraint, not preference: a separate worker service cannot mount the Railway volume, so it could not delete photo files, failing INV-07 outright. | advisory | Read `04-DISCUSSION-LOG.md` § Expiry Cleanup before reopening. |

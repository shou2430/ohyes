## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing, input padding |
| md | 16px | Default element spacing, card padding |
| lg | 24px | Section padding, form field gaps |
| xl | 32px | Layout gaps between major sections |
| 2xl | 48px | Page top/bottom padding |
| 3xl | 64px | Not used in this phase |

Exceptions: Touch targets on mobile must be minimum 44px height (h-11 class, already established in Phase 1 buttons).

## Typography

| Role | Size | Weight | Line Height | Tailwind |
|------|------|--------|-------------|----------|
| Body | 14px | 400 (regular) | 1.5 | `text-sm` |
| Base | 16px | 400 (regular) | 1.5 | `text-base` |
| Heading | 20px | 600 (semibold) | 1.2 | `text-xl font-semibold` |
| Display | 24px | 600 (semibold) | 1.2 | `text-2xl font-semibold` |
| Caption | 12px | 400 (regular) | 1.4 | `text-xs` |

Caption is a sub-scale utility size used for inline hints, character counters, and format notes (e.g., photo format hint, password helper text, character counter). Not a primary typographic role — used only for supplementary information adjacent to form fields.

Source: Inherited from Phase 1 patterns. Landing uses `text-4xl font-semibold` for app title, dashboard uses `text-2xl font-semibold` for headings, `text-base` for body, `text-sm` for labels and buttons.

## Component Inventory

### Page: Dashboard (updated from Phase 1 empty state)

**Focal Point:** The invitation card(s) — specifically the title row of the topmost card. When no invitations exist, the empty-state CTA button is the focal point. The accent-colored "Create Invitation" button serves as the secondary draw.

#### Top Bar
- Inherited from Phase 1 unchanged. App name left, avatar + name + logout right.
- Height: `h-16`, border-bottom, white background.

#### Invitation Card (new)
- Container: Full-width white card, `rounded-lg`, `border border-border`, `p-4 sm:p-6`.
- Layout: Vertical stack with `gap-3`.
- **Row 1 — Title:** `text-xl font-semibold text-text-primary`. Truncate with `truncate` if overflow.
- **Row 2 — Metadata:** `text-sm text-text-secondary`. Format: "Created [date] -- [N] days remaining". Use interpunct or em-dash separator.
- **Row 3 — Password:** `text-sm text-text-secondary`. Label "Password:" followed by masked dots (`* * * * * *`) by default. Toggle button (Eye/EyeOff icon from Lucide, 16px) reveals plain text. Toggle state is local per card.
- **Row 4 — Actions:** Horizontal row with `gap-2`, right-aligned on desktop, full-width stacked on mobile.
  - "Copy link" button: `h-9 px-4 rounded-lg border border-border bg-white text-sm font-medium text-text-primary hover:bg-stone-50`. Lucide `Link` icon (16px) left of text. On click, copies URL to clipboard and text changes to "Copied!" for 2 seconds, then reverts.
  - "Delete" button: `h-9 px-4 rounded-lg border border-destructive text-sm font-medium text-destructive hover:bg-red-50`. Lucide `Trash2` icon (16px) left of text. On click, triggers `window.confirm("Delete this invitation? This cannot be undone.")`. On confirm, calls DELETE API and removes card from list.

#### Create Button Area
- When user has 0-1 invitations: Active accent button. Same style as Phase 1 CTA: `h-11 rounded-lg bg-accent text-sm font-medium text-white hover:scale-[1.02] transition-transform`. Full width on mobile, `min-w-[200px] px-6` on `sm:`. Navigates to `/create`.
- When user has 2 invitations: Disabled state. `opacity-50 cursor-not-allowed`. Below button: `text-sm text-text-secondary mt-2` with message (see Copywriting).
- Position: Below card list, centered. `mt-6`.

#### Empty State (existing, retained)
- Centered vertically. Heading + body + CTA button. Already implemented in Phase 1.

### Page: Create Invitation (`/create`)

**Focal Point:** The form card — specifically the title input field as the first interactive element. On large screens with the two-column layout, the live preview panel acts as a secondary focal point drawing the eye rightward after the form is engaged.

#### Layout
- Full page, `min-h-screen bg-cream`.
- Top section: Back navigation. Lucide `ArrowLeft` icon (20px) + "Back to Dashboard" link. `text-sm text-text-secondary hover:text-text-primary`. Positioned `px-4 sm:px-8 pt-4`.
- Content: Two-column layout on `lg:` (form left, preview right). Single column stacked on mobile (form on top, preview below).
- Form column: White card container, `rounded-lg border border-border p-6 sm:p-8`. Max width `max-w-lg`.
- Preview column: Sticky preview panel, `lg:sticky lg:top-8`. Max width `max-w-sm`.

#### Form Fields

**Title field:**
- Label: `text-sm font-medium text-text-primary mb-2` — "Title"
- Input: `h-11 w-full rounded-lg border border-border px-3 text-base text-text-primary placeholder:text-text-secondary focus:border-accent focus:ring-1 focus:ring-accent outline-none transition-colors`
- Placeholder: "Will you...?"
- Required. No max length specified in requirements (title text is free-form).
- Error state: `border-destructive focus:border-destructive focus:ring-destructive`. Error message below: `text-sm text-destructive mt-1`.

**Photo upload:**
- Label: `text-sm font-medium text-text-primary mb-2` — "Photo"
- Upload area (no photo selected): Dashed border rectangle, `h-40 w-full rounded-lg border-2 border-dashed border-border flex items-center justify-center cursor-pointer hover:border-accent hover:bg-cream/50 transition-colors`. Interior: Lucide `ImagePlus` icon (32px, `text-text-secondary`) above `text-sm text-text-secondary` "Click to upload a photo". Below that: `text-xs text-text-secondary` "JPG, PNG, or WebP. Max 5 MB."
- Upload area (photo selected): Replace dashed area with image preview. `h-40 w-full rounded-lg object-cover`. Overlay on hover: semi-transparent dark overlay with "Change photo" text and Lucide `RefreshCw` icon. Click to re-open file picker.
- Hidden `<input type="file" accept="image/*">` triggered by click on upload area.
- Error: "File too large. Maximum size is 5 MB." in `text-sm text-destructive mt-1`.

**Password field:**
- Label: `text-sm font-medium text-text-primary mb-2` — "Password"
- Input: Same styling as title input. `type="text"` by default (visible, per D-16). Toggle button inside input (right side): Lucide `EyeOff`/`Eye` icon (16px), `text-text-secondary hover:text-text-primary`.
- Character counter: Right-aligned below input. `text-xs text-text-secondary`. Format: "N/8 characters". Turns `text-destructive` when count < 4 or > 8 after user has started typing.
- Placeholder: "Set a password for your recipient"
- Helper text: `text-xs text-text-secondary mt-1` — "4-8 characters. This is a personal touch, not a security feature."
- Error: "Password must be 4-8 characters" in `text-sm text-destructive mt-1`.

**Submit button:**
- `h-11 w-full rounded-lg bg-accent text-sm font-medium text-white hover:scale-[1.02] transition-transform mt-6`
- Label: "Create Invitation"
- Loading state: Text changes to "Creating..." with a spinner (reuse LoadingSpinner pattern or inline SVG spinner). Button disabled during submission.
- Disabled when form is invalid (missing required fields): `opacity-50 cursor-not-allowed`.

#### Inline Preview Panel

- Container: `rounded-lg border border-border bg-white p-4 sm:p-6`.
- Heading: `text-sm font-medium text-text-secondary mb-3` — "Preview"
- Preview content:
  - Title: Renders the title input value in real-time. `text-xl font-semibold text-text-primary`. Shows placeholder text "Your title here" in `text-text-secondary` when empty.
  - Photo: Shows uploaded photo as `rounded-lg object-cover w-full aspect-[4/3]`. Shows a light gray placeholder rectangle (`bg-stone-100 rounded-lg w-full aspect-[4/3] flex items-center justify-center`) with Lucide `Image` icon (48px, `text-stone-300`) when no photo uploaded.
  - Buttons: Static non-interactive preview of "Yes" (accent bg) and "No" (outlined) buttons below the photo. `text-sm rounded-lg h-9 px-6`. These are decorative only -- not clickable in preview.

### Modal: Success (post-creation)

- Overlay: `fixed inset-0 bg-black/50 z-50 flex items-center justify-center p-4`.
- Modal body: `bg-white rounded-xl p-6 sm:p-8 max-w-sm w-full shadow-lg`.
- Content:
  - Lucide `CheckCircle` icon (48px, `text-accent`) centered.
  - Heading: `text-xl font-semibold text-text-primary mt-4 text-center` — "Invitation Created!"
  - Body: `text-sm text-text-secondary mt-2 text-center` — "Share this link with your special someone."
  - URL display: `mt-4 rounded-lg bg-cream p-3 text-sm text-text-primary font-mono break-all text-center` — shows full URL.
  - Copy button: `h-11 w-full rounded-lg bg-accent text-sm font-medium text-white hover:scale-[1.02] transition-transform mt-4`. Label: "Copy Link". On click: copies to clipboard, text changes to "Copied!" for 2 seconds.
  - Dismiss: `text-sm text-text-secondary mt-3 text-center cursor-pointer hover:text-text-primary` — "Back to Dashboard". Navigates to `/dashboard`.
- Close on backdrop click: Yes.
- Close on Escape key: Yes.

### Page: Expired/Deleted Invitation (`/i/:code` — invalid code)

- Full page, `min-h-screen bg-cream flex items-center justify-center px-4`.
- Centered content, `max-w-[320px] text-center`.
- Lucide `HeartCrack` icon (48px, `text-text-secondary`) centered.
- Heading: `text-2xl font-semibold text-text-primary mt-4` — "This invitation has expired"
- Body: `text-base text-text-secondary mt-2` — "This invitation has expired or been removed."
- Link: `text-sm text-accent hover:underline mt-4 inline-block` — "Go to OhYes". Links to `/`.

## Interaction Contracts

### Dashboard Card — Copy Link
1. User clicks "Copy link" button.
2. URL is written to clipboard via `navigator.clipboard.writeText()`.
3. Button text changes to "Copied!" with Lucide `Check` icon replacing `Link` icon.
4. After 2000ms, text and icon revert to default.
5. If clipboard API fails, show toast error.

### Dashboard Card — Delete
1. User clicks "Delete" button.
2. Browser `window.confirm()` dialog appears with confirmation copy (D-14).
3. If confirmed: DELETE API call fires. Card fades out (`opacity-0 transition-opacity duration-200`) and is removed from DOM. If user had 2 invitations, "Create" button re-enables.
4. If cancelled: No action.
5. If API fails: Toast error notification.

### Dashboard Card — Password Reveal
1. Default state: Password masked as dots.
2. User clicks Eye icon: Password revealed as plain text. Icon changes to EyeOff.
3. User clicks EyeOff icon: Password re-masked. Icon changes to Eye.

### Create Form — Photo Upload
1. User clicks upload area or existing photo preview.
2. Native file picker opens (`accept="image/*"`).
3. On file select: Client validates file size (< 5 MB). If too large, show inline error, do not set file.
4. If valid: Show image preview in upload area and in preview panel. Store file reference for form submission.

### Create Form — Live Preview
1. Title input `onChange` updates preview title in real-time.
2. Photo file selection updates preview photo immediately (via `URL.createObjectURL`).
3. Preview panel shows static Yes/No button mockups (non-interactive).

### Create Form — Submission
1. Client-side validation: title required, photo required, password 4-8 characters.
2. If invalid: Show field-level errors. Do not submit.
3. If valid: Disable button, show "Creating..." with spinner. POST to API with `multipart/form-data` (title, password, photo file).
4. On success: Show success modal with shareable URL. Do not navigate yet.
5. On failure: Re-enable button. Show toast error.

### Success Modal — Dismiss
1. User clicks "Back to Dashboard", clicks backdrop, or presses Escape.
2. Navigate to `/dashboard`. New invitation appears in card list.

### Toast Notifications
- Position: Fixed, top-center. `fixed top-4 left-1/2 -translate-x-1/2 z-50`.
- Style: `bg-white rounded-lg border border-border shadow-lg px-4 py-3 text-sm text-text-primary`.
- For errors: Left border accent `border-l-4 border-l-destructive`.
- Auto-dismiss after 5000ms. No manual close button needed for v1.
- Animation: Slide down from top, fade out on dismiss.

## Accessibility

- All form inputs have associated `<label>` elements (not just visual labels).
- Upload area is keyboard-accessible: `tabIndex={0}`, triggers file picker on Enter/Space.
- Password toggle button has `aria-label="Show password"` / `aria-label="Hide password"`.
- Success modal traps focus while open. First focusable element (Copy Link button) receives focus on open.
- Delete confirmation uses native `window.confirm()` which is inherently accessible.
- Copy link feedback ("Copied!") announced via `aria-live="polite"` region.
- Color contrast: All text/background combinations meet WCAG AA (text-primary on cream = 14.5:1, text-secondary on cream = 5.2:1, white on accent = 4.6:1).
